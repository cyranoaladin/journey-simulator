# LIVRABLE S2.2 — PERSISTENCE & MODÈLES

**Statut** : LIVRÉ / EN ATTENTE DE VALIDATION
**Date** : 2025-12-24
**Source** : `ANALYSIS_S2.1.md`

## 1. FICHIERS CRÉÉS
Les fichiers suivants ont été créés pour implémenter la couche de persistance S2 :

*   `mf-back/models/JourneyRun.js` : Racine du parcours (State Machine).
*   `mf-back/models/PhaseProgress.js` : État mutable d'une phase.
*   `mf-back/models/Submission.js` : Archive immuable des inputs utilisateur (Append-only).
*   `mf-back/models/Evaluation.js` : Verdict immuable (Append-only).
*   `mf-back/models/XpLedger.js` : Comptabilité immuable de l'expérience.
*   `mf-back/__tests__/s2_models.test.js` : Tests unitaires de validation et d'immutabilité.

## 2. SCHÉMAS DE DONNÉES FINAUX
Les modèles Mongoose implémentent strictement les spécifications de S2.1.
Points clés :
*   **Immutabilité** : Les modèles `Submission`, `Evaluation`, `XpLedger` disposent d'un hook `pre('save')` qui rejette toute modification (`!this.isNew`).
*   **Énumérations** : Les status (`LOCKED`, `VALIDATED`, etc.) sont forcés au niveau du schéma.
*   **Relations** : Les clés étrangères (`userId`, `runId`, `submissionId`) sont typées `ObjectId`.

## 4. LIMITES DE S2.2
Ce livrable couvre uniquement la **structure de données**.
*   Aucune API REST n'est exposée pour ces modèles.
*   Aucune logique métier (calcul de score, transition automatique) n'est implémentée.
*   Le frontend `journey-simulator` n'utilise pas encore ces modèles.
*   Les tests nécessitent une instance MongoDB locale active.

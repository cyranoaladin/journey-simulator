# LIVRABLE S2.3 — LOGIQUE & API MOTEUR

**Statut** : LIVRÉ / EN ATTENTE DE VALIDATION  
**Date** : 2025-12-24  
**Source** : `ANALYSIS_S2.1.md`

## 1. COMPOSANTS CRÉÉS

### Logic Layer (Service)
*   **Fichier** : `mf-back/services/JourneyEngine.js`
*   **Rôle** : Implémente la "Vérité Serveur".
*   **Transitions Appliquées** :
    *   `startJourney` : Crée un Run, débloque Phase 1.
    *   `submitPhase` : Vérifie le statut (`UNLOCKED` uniquement), crée une `Submission` (immutable), passe la Phase à `SUBMITTED`.
    *   `mockEvaluate` : (Dev only) Simule le retour Zyno (`SUBMITTED` -> `VALIDATED`/`REJECTED` + Attribution XP).

### API Layer
*   **Controller** : `mf-back/controllers/journey-engine-controller.js`
*   **Router** : `mf-back/routes/journey-engine-routes.js`
*   **Endpoints** (Protegés via JWT/Demo-Token) :
    *   `POST /start` : Démarrage idempotente par définition/user.
    *   `POST /submit` : Envoi de preuve.
    *   `GET /:id/state` : Récupération de l'état complet (Run + Phases).
    *   `POST /advance` : (Dev) Trigger d'évaluation.

## 2. PREUVE DE CONFORMITÉ (TESTS)

Deux suites de tests valident le fonctionnement :

### Tests Logique (`s2_logic.test.js`)
Valident les règles métier sans passer par HTTP.
*   Preuve que soumettre sur une phase `LOCKED` échoue.
*   Preuve que l'immutabilité des `Submission` est respectée par le service.
*   Preuve du calcul XP (Mock) et du déblocage séquentiel.

### Tests API (`s2_api.test.js`)
Valident l'exposition HTTP.
*   Utilisation de `supertest` avec mounting isolé de la route.
*   Validation des codes HTTP (201 Created, 400 Bad Request, 200 OK).
*   Compatible avec le middleware `auth` existant (testé avec `demo-token`).

## 3. ABSENCE DE RISQUE (ISOLATION)
*   Le fichier `app.js` principal n'a **PAS** été modifié. Le simulateur existant (Frontend `journey-simulator`) continue de fonctionner sur les anciennes routes `/journey/*`.
*   Les nouvelles routes sont prêtes à être montées (recommandé : `/api/engine/v1`) lors de la phase d'intégration S2.5.

## 4. LIMITES S2.3
*   L'évaluation est simulée (`mockEvaluate`). La vraie intégration Zyno (Agents) est prévue en S2.4.
*   Le calcul XP est une formule placeholder (`score * 10`).
*   Aucun hash cryptographique réel n'est généré (S3).

## 5. PROCHAINE ÉTAPE (S2.4)
Intégration réelle avec Zyno :
*   Remplacer `mockEvaluate` par un appel asynchrone aux Agents.
*   Gérer le feedback loop réel.

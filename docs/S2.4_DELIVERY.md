## 1. COMPOSANTS CRÉÉS

### Evaluation Service
*   **Fichier** : `mf-back/services/EvaluationService.js`
*   **Rôle** : Reçoit une soumission et produit un verdict (Score + Decision + Metrics).
*   **Modes** :
    1.  **Deterministe** (Défaut) : Analyse basique (ex: présence de payload). Utilisé pour la robustesse.
    2.  **LLM-Assisted** (Activé via `ENABLE_ZYNO_EVAL=true`) : Appelle `ZynoAgent` pour une analyse sémantique.
*   **Résultat** : Persiste une `Evaluation` immutable et prépare l'entrée `XpLedger`.

### Mise à jour JourneyEngine (S2.3 -> S2.4)
*   **Changement** : `submitPhase` appelle désormais **synchrotement** `EvaluationService.evaluate`.
*   **Transition Automatique** :
    *   `UNLOCKED` -> `SUBMITTED` -> (Eval Pass) -> `VALIDATED` + Unlock Next.
    *   `UNLOCKED` -> `SUBMITTED` -> (Eval Fail) -> `REJECTED`.
*   **Suppression** : La méthode `mockEvaluate` (S2.3 dev only) a été remplacée par cette intégration native.

## 3. ZYNO INTEGRATION
*   Le code pour l'appel à `ZynoAgent` est en place dans `EvaluationService.js` (Lignes 18-50).
*   Il est protégé par un `try/catch` et un `env check`. Si Zyno échoue ou n'est pas configuré, le système fallback sur le mode déterministe, garantissant que le User n'est jamais bloqué ("Safe Failover").

## 4. LIMITES S2.4
*   Le mode Zyno dépend d'une clé API OpenAI valide. En test local (CI) sans clé, le fallback est utilisé.
*   Les règles d'XP restent basiques (Score * 10).
*   Pas encore de Proof-of-Skill cryptographique (S3 scope).
